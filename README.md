# Шёпот — чат со сквозным шифрованием

Next.js + Socket.IO приложение, в котором сервер **не умеет читать сообщения**: клиенты
шифруют текст друг для друга прямо в браузере, подписывают его своими ключами, а сервер
лишь проксирует шифрованные пакеты и раздаёт открытые ключи. Групповые чаты собираются
по ссылке-приглашению (опционально — с секретной фразой), история не хранится нигде:
все действующие чаты живут только в оперативной памяти сервера.

## Как это работает (протокол v2)

```
Браузер А                                Сервер (RAM-only)                     Браузер Б
─────────                                ─────────────────                     ─────────
ECDH P-256 + ECDSA P-256   ── jwk ──▶   rooms: Map<roomId,                    ◀── jwk ──  ECDH P-256 + ECDSA P-256
                                           Map<socketId, {name, publicKey}>>
                                         при входе новичка:
                                           всем старожилам ──▶ member:joined {ключи новичка}
                                           новичку ─────────▶ ack {ключи всех старожилов}

сообщение:  текст ──подпись ECDSA──▶ canonical v2|room|from|seq|ts|text
            AES-256-GCM(ключ A↔B, AAD=room|from|seq) ──{to,seq,ts,sig,iv,data}──▶
                                           msg:send ──▶ msg:new ──▶ расшифровка + verify(ECDSA)
```

1. При открытии страницы браузер генерирует **две пары P-256**: ECDH (шифрование)
   и ECDSA (подписи). Приватные ключи никогда не покидают вкладку.
2. Вход по коду (8 символов): новичок получает открытые ключи всех участников,
   участники — ключи новичка.
3. Ключ сообщений для каждого собеседника: ECDH → HKDF → AES-256-GCM.
   Если задана **секретная фраза комнаты**, она входит в HKDF-info и серверу не
   передаётся вовсе — сервер без фразы не может провести MITM-подмену ключей.
4. Каждое сообщение подписывается ECDSA (canonical `v2|room|from|seq|ts|text`) —
   сервер не может подделать отправителя; сбой проверки помечается «подпись не проверена».
5. AES-GCM AAD = `roomId|senderId|seq` + монотонный `seq` — replay и переигрывание
   шифротекста между комнатами невозможны.
6. При смене отпечатка ключа под видом того же имени клиент показывает жёлтое
   предупреждение (детекция MITM-подмены). Отпечатки SHA-256 видны в панели участников.
7. При выходе участника его ключи удаляются; пустые комнаты удаляются из RAM.
   Перезапуск сервера стирает все чаты — истории нет по построению.

## Запуск

```bash
npm install
npm run dev        # дев-режим, http://127.0.0.1:3000
```

Production:

```bash
npm run build
npm start          # NODE_ENV=production, http://127.0.0.1:3000
```

Деплой на Google Cloud Run (контейнер, без рерайта): см. [DEPLOY.md](DEPLOY.md).

Сервер по умолчанию слушает **только 127.0.0.1**. Публичный доступ — осознанно:
`HOST=0.0.0.0 PORT=3000 npm start` за reverse-proxy с TLS (Web Crypto требует
secure context: localhost или HTTPS). Здоровье: `GET /healthz` (полные метрики —
только с loopback).

Протестировать протокол без браузера (сервер должен быть запущен):

```bash
node test/e2e-protocol.mjs          # 13 проверок, включая tamper/replay/фразу
PORT=3100 node test/e2e-protocol.mjs
```

## Защиты (security)

- **Крипто:** ECDH P-256 + HKDF + AES-256-GCM (AAD), подписи ECDSA P-256,
  анти-replay (seq), секретная фраза комнаты в KDF, детектор смены отпечатков.
- **Сервер:** rate-limit на join (5/10с) / typing (10/10с) / сообщения (40/10с),
  ≤10 соединений на IP, ≤2000 сокетов, ≤1000 комнат, ≤32 участника, лимиты размеров
  (16 КБ/шифротекст, подпись ≤512 B), проверка Origin подключений, NFKC-нормализация
  имён с вырезанием невидимых/bidi-символов, привязка на 127.0.0.1.
- **Заголовки:** CSP, X-Content-Type-Options, X-Frame-Options: DENY, Referrer-Policy,
  Permissions-Policy (см. `next.config.js`).
- **Зависимости:** next 14.2.35, express 4.22.x, postcss 8.5.x (override). Известный
  остаток: кластер advisories против next <16 (Image Optimizer/RSC/middleware) — векторы
  не применимы к нашему профилю (нет middleware, images, server actions); запланировать
  отдельную миграцию на Next 16.

## Возможности интерфейса

- Групповые чаты до 32 участников, вход по коду/ссылке `#EXFKPEQE`, вставка полной
  ссылки в поле кода, опциональная секретная фраза с генератором.
- Эмодзи-пикер: 8 категорий, поиск по-русски, «недавние», вставка в курсор.
- Индикатор «печатает…», статусы подключения, автопереподключение с перезаходом
  теми же ключами, автоскролл с непрочитанными, группировка сообщений.
- Адаптив: ≥1024px сайдбар; <1024px drawer; <640px тач-цели, safe-area, 16px поля,
  `100dvh` + `interactive-widget` под виртуальную клавиатуру.

## Протокол (Socket.IO)

| Событие        | Направление     | Payload |
|----------------|-----------------|---------|
| `room:join`    | клиент → сервер | `{roomId, name, publicKey:{ecdh,ecdsa}}` → ack `{ok, self, members[]}` |
| `member:joined`| сервер → комната| `{id, name, publicKey:{ecdh,ecdsa}}` |
| `msg:send`     | клиент → сервер | `{payloads: [{to, seq, ts, sig, iv, data}]}` (только шифротекст+подпись) |
| `msg:new`      | сервер → адресат| `{from, fromName, seq, ts, sig, iv, data}` |
| `typing`       | обе стороны     | `{typing: boolean}` |
| `member:left`  | сервер → комната| `{id, name}` |
| `room:leave`   | клиент → сервер | — |

## Границы безопасности (честно)

- Сообщения защищены от пассивного наблюдения и от подделки авторства; метаданные
  (факт, время, имена, typing) сервер видит — by design
- Подмена ключей при первом входе обнаруживается только сверкой отпечатков
  (TOFU + предупреждение о смене ключа). Секретная фраза комнаты закрывает и первый
  вход: без неё сервер не может вывести ключи пары.
- Нет forward secrecy внутри сессии: статические ключи на вкладку; при компрометации
  устройства расшифровывается сессия. Усиление — periodic re-key / Double Ratchet.
- Приватные ключи WebCrypto — extractable (общий флаг пары, ограничение платформы);
  главный компенсатор — CSP против XSS.
- CSP содержит `'unsafe-inline'` для скриптов (требование App Router); nonce-CSP —
  будущее усиление.
