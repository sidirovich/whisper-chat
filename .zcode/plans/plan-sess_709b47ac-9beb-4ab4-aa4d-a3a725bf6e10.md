Полный пакет устранения уязвимостей «Шёпота». Протокол поднимается до v2 (старых клиентов нет — единый деплой), после доработки — полная перерегрессия.

## 1. Зависимости (п.5 отчёта)
- `npm install next@^14.2 express@^4.21` (последние патчи веток), затем `npm audit` — добить до 0 известных уязвимостей.

## 2. Сервер: анти-абьюз и сетевая гигиена (п.3, 4, 8, 10)
В `server.js`:
- Убрать `cors: { origin: true }`; добавить connection-middleware: если заголовок `Origin` присутствует и его host ≠ `Host` запроса — отклонять (защита от чужих веб-страниц; curl/нативные клиенты без Origin проходят).
- Rate-limit по sliding window (как у msg): `room:join` ≤ 5/10с, `typing` ≤ 10/10с на сокет.
- Лимиты: ≤10 соединений на IP, ≤2000 соединений всего, ≤1000 комнат (новые сверх cap — отказ).
- `HOST` по умолчанию `127.0.0.1` (наружу — только осознанно через env + reverse-proxy).
- `/healthz`: полный JSON только с loopback, снаружи — `{ok:true}`.
- Имена: NFKC-нормализация, вырезание bidi/zero-width символов (U+200B-200F, U+202A-202E, U+2066-2069, U+FEFF), схлопывание пробелов.
- Коды комнат: создание новой комнаты требует длину ≥8; вход в существующую — 6–10 (клиент генерирует 8).
- Валидация конверта v2: `seq` (число 0..2^31), `sig` (base64 ≤512 символов), `ts` (число).

## 3. Криптоусиление (п.1, 2, 6)
`lib/crypto.ts`:
- Двойная пара на клиента: ECDH P-256 + **ECDSA P-256** (подпись/проверка). `publicKey` в room:join = `{ ecdh: JWK, ecdsa: JWK }`.
- `encryptText/decryptText` принимают **AAD**; AAD = `roomId|senderId|seq`.
- `deriveAesKey` включает **секретную фразу комнаты** в HKDF-info (сервер её никогда не видит; MITM-сервер не сможет вывести ключи пары).
- Отпечаток — SHA-256 от обоих публичных ключей.

`lib/useChat.ts`:
- Отправка: canonical `v2|roomId|from|seq|ts|text` → ECDSA-подпись; конверт `{to, seq, ts, sig, iv, data}`.
- Приём: расшифровка с AAD → проверка подписи → анти-replay (`seq` монотонный на отправителя, повтор/откат отбрасывается с системным предупреждением); сбой подписи — сообщение с пометкой «не проверено» (warn-стиль).
- **Детектор смены ключа**: карта имя→отпечаток; при несовпадении — жёлтое системное «Ключ участника X изменился — сверьте отпечаток».

## 4. Комнатные секреты и UX (п.7, 8)
- `components/JoinScreen.tsx`: необязательное поле «Секретная фраза» (передаётся только в локальную KDF, не на сервер); при создании комнаты фраза предлагается сгенерировать (словарная passphrase из 4 слов).
- `makeRoomCode`: 8 символов; `parseRoomCodeFromUrl`/инпут — 6–10.
- Ошибка расшифровки при неверной фразе сопровождается подсказкой «возможно, неверная секретная фраза».

## 5. Заголовки (п.4)
`next.config.js` → `headers()`: CSP (`default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src 'self' ws: wss:; object-src 'none'; base-uri 'self'; frame-ancestors 'none'`; ограничение 'unsafe-inline' для скриптов — фундамент App Router, nonce-CSP отметить в README как будущее усиление), `X-Content-Type-Options`, `X-Frame-Options: DENY`, `Referrer-Policy: same-origin`, `Permissions-Policy`.

## 6. Тесты и регрессия
- `test/e2e-protocol.mjs` расширить: двойной обмен ключами, проверка подписи, tamper-кейс (битый sig → непроверено, подмена seq → replay-отказ, неверная фраза → decrypt fail).
- Прогон: `tsc --noEmit` → `next build` → перезапуск сервера (taskkill + npm start) → протокольный тест → браузерный smoke двух вкладок с секретной фразой.
